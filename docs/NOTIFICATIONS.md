# Notifications
Adapters (plain HTTPS, no extra dependencies): Resend (e-mail), Twilio (SMS), WhatsApp Cloud API. A channel is active only when its env vars are set; otherwise outbox rows get `no_provider` — nothing is pretended as sent. **Not verified against the live services** (no network when written): tests cover request shape, escaping, E.164 checks and error handling only (`providers/notify.ts`).
Templates (`templates.ts`, AR+EN): booking_created, appointment_confirmed, appointment_reminder, order_update, subscription_notice, payment_confirmation, verify_email, password_reset. Retry: `startOutboxWorker` re-sends failed messages (max 3 attempts, back-off 2^n minutes from creation). Delivery receipts (webhooks) and per-user notification preferences are NOT implemented. Triggers wired: booking_created, appointment_confirmed (medical), appointment_reminder (medical/booking, hourly worker), order_update (e-commerce), payment_confirmation and failed-payment subscription_notice (to the owner, real gateways only), verify_email, password_reset. Not wired: other products' status e-mails.
WhatsApp: outside the 24-hour window Meta requires an approved template — set `WHATSAPP_TEMPLATE_NAME`.

## Update (fourth pass)
- **Delivery tracking:** the provider's message id is stored (`notification_outbox.provider_id`); receipts update the status (`sent` → `delivered` → `read`, or `failed`, never downgraded). Twilio: `POST /api/v1/webhooks/twilio-status` (signature checked with `TWILIO_AUTH_TOKEN`; needs `PUBLIC_API_URL`). WhatsApp: `GET/POST /api/v1/webhooks/whatsapp` (`WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_APP_SECRET`). **E-mail (Resend) receipts are not implemented.** Signature logic follows the providers' documentation and is tested against independent computations only, not against the live services.
- **Status e-mails/SMS** for booking (confirmed/cancelled/completed), automotive (ready/delivered), fleet (out for delivery/delivered/failed attempt) and restaurant (ready/out for delivery), on top of medical/e-commerce. SMS numbers are normalised to E.164 (`01012345678` → `+201012345678`).
- **Preferences:** Settings → outgoing customer notifications (channels, appointment messages, order/status updates). Opted-out messages are recorded as `opted_out`. Account messages (verify/reset/billing) cannot be switched off.
- **Renewal reminders:** owner e-mail 3 days before a period/trial ends (with a link to Billing when `PUBLIC_WEB_URL` is set).

## Fifth pass additions
* **E-mail delivery receipts (Resend):** `POST /api/v1/webhooks/resend`, signed with Svix (`svix-id`, `svix-timestamp`, `svix-signature`, secret = `RESEND_WEBHOOK_SECRET`, 5-minute replay window). `email.delivered` → `delivered`, `email.bounced` / `email.complained` / `email.failed` → `failed` with a reason, `email.sent` → `sent`; opens/clicks are ignored (no tracking). A delivered message is never downgraded. Not verified against the live service.
* **Account e-mails** (verification, password reset for owners/staff) use `enqueueSystem`: they ignore the business's notification preferences and plan entitlements, so a business cannot switch off its own password reset.
