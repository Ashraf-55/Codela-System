# Customer / patient / student portal
Public path `/portal` on a tenant site (preview: `/sites/<slug>/portal`). Separate account table (`portal_accounts`, per tenant) and sessions (`psid`/`pcsrf` cookies, CSRF double-submit). A session is bound to its tenant and rejected on any other host.
"My records" links the account to the tenant's patient/student/customer record **by e-mail**, so e-mail verification is mandatory in production (`PORTAL_REQUIRE_EMAIL_VERIFICATION`, default on when cookies are secure). Whitelisted fields only (`PORTAL_MAP` in `portal.ts`): staff notes are never returned. Supported: medical (appointments), booking (appointments), ecommerce (orders), learning (enrollments, certificates).
From inside the portal: learning → enrol in courses; booking → pick service/date, see real free slots, book; medical → send an appointment request (the clinic confirms). Not built: ordering from inside the portal for e-commerce/restaurant (link to the storefront), course lesson viewer, assignments, payment history for end customers, per-customer notification preferences. Accounts lock for 15 minutes after 5 wrong passwords. Public forms/actions on the site still cover booking/ordering/enrolment.

## Fifth pass additions
* **Profile picture:** `GET/PUT/DELETE /public/portal/avatar` (customers) and `GET/PUT/DELETE /auth/me/avatar` (owners/staff). Magic-byte validated, max 2 MB, private, only the owner can read it, previous file deleted on replace, counts toward the plan storage quota.
* **Notifications list:** `GET /public/portal/notifications` — booking/appointment/order/payment messages sent to the account e-mail. Verification and reset links are never listed. `delivery` is `sent` only when a provider accepted the message; `pending` while queued; otherwise `not_delivered`.
* **Payment history:** `GET /public/portal/payments` — medical invoices (not drafts), booking appointments, e-commerce orders, course enrolments of THEIR OWN record: total, paid, balance, status. Read-only.
* **Student learning (`portal-learning.ts`):** lesson viewer (text body + external content URL, preview lessons open before payment), mark lesson complete (drives progress %), live sessions, exams (questions without answers, attempt limit, exact grading), assignments (submit once, deadline enforced, staff grade from the dashboard), certificate request (only after all lessons + exams). Writes use the same entity hooks as the dashboard, so payment / expiry rules cannot be bypassed.
* **New learning entities:** `assignment`, `submission` (dashboard modules `assignments`, `submissions`; employees may read assignments and grade submissions).
* **Not done:** ordering from inside the customer account for e-commerce / restaurant (the account links to the website pages); a server-side exam timer (`durationMin` is informational).
